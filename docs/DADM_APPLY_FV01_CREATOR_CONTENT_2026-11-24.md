## Data and API contract

A stdlib-only deterministic builder `tools/build_creator_locale.py` consumes reviewed `tools/creator_locale/pins.json` plus separate approved non-entity term references. It emits `srd-5.2.1-en/generated/creator-display.json`, supporting `--check`. Entity display names come directly from actual EN entities; references identify genuine source entries. Pin compendium and referenced-document hashes so source drift fails generation until reviewed. Require both compendia and canonical creator-data in the pin set; verify all non-null model IDs and subclass feature reference graphs are covered; three reading-only core feature headings (count-suffixed progression labels lack IDs) require actual source anchors in a canonical class document; reject other unreferenced identities and unsupported source-difference fields. Terms match source words at boundaries. No creator-data/model mutation or second mechanics engine.

The bounded target is 663 core/spell names and 52 terms (six abilities, eighteen skills, nineteen languages, nine alignments). Terms retain canonical IDs and use exact EN source text, with block references/quotes validated by the builder; short ability abbreviations use source-backed English notation. Equipment names, subchoices, remaining rule-derived labels, structured findings and the sheet/editor remain outstanding and stay visible as partial language support.

Authenticated `GET /api/srd-creator/creator-display?locale=de|en` returns locale, schema version, canonicalHash, source hashes, ID-keyed name/English-entry data, terms, source differences, coverage and unresolved collections. Default DE; invalid locale 400. Responses are private/no-cache with an ETag so overlay-only corrections are revalidated; missing/stale generated EN data returns a non-cacheable 503. The existing canonical `/creator-data` body remains byte-for-byte equivalent as JSON data, with an additive `X-Creator-Data-SHA256` header identifying its pinned canonical source. English requests add `v=<hash>`; clients reject payload/header mismatch. This exposes no user data and grants no new permissions.

## Client contract

Keep `app.data`, lookups, derived values and every logic comparison canonical. Introduce explicit presentation helpers for names/terms/class labels. Replace display emissions only; retain canonical comparisons such as `f.name === bg.feat`, feat category and weapon properties. Homebrew and user names/text are never mapped by string similarity. Search and sorting use localized spell names and the module locale; search also retains the canonical-name alias.

Load the English overlay on English creator entry and rules-locale change. Cache only a hash-matching overlay; monotonically increasing locale/request sequence counters discard old responses. Overlay failure leaves editing/saving/finalizing usable with German names and a visible translated notice. The existing partial-language notice remains until the full packet closes. Use explicit language markers for mapped name labels/options and canonical fallback where feasible; genuine rule blocks always carry their actual language.

Locale-only control capture must now use stable canonical control identities for reordered spell/choice rows, rather than global checkbox positions. Include caster/list/spell in each spell-control key. Exclude async subclass disclosures from positional details restore to prevent shifting other groups; their previous own reset remains open. Add canonical focus keys to choice widgets; preserve IDs, selected/checked values, pending-input flags, focus/selection and view state. Retain the previous finalization subtree and selected import file behavior.

Rule dialogs resolve a canonical ID through the approved overlay and fetch its genuine EN entry; absent mappings explicitly fall back to DE with a notice and `lang=de`. Homebrew retains authored text. Separate dialog/locale counters prevent slow older entries or languages overwriting the current dialog, including after closure. A locale change refreshes an open detail after its overlay is ready. Source-difference notices remain separate from unmodified source blocks. Existing subclass previews receive a source resolver and use an explicit feature-ID index built from genuine EN class-feature entities in the mapped subclass's document/name context (the actual EN subclass entity has no `features` list), validated against the reviewed mapping and ordered by source anchors, with explicit DE fallback when an EN preview cannot load; other callers retain the previous default until their own module slice.
