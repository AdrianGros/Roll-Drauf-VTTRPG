# Codex interpretation of the mapmaker reviews

**Phase:** DAD-M Monitor. **Status:** review complete with a required functional follow-up; security acceptance remains incomplete. **Input:** first-use journeys, action coverage, visual structure, completeness, VTT branding, and independent Claude penetration testing. Claude Opus5.5 finished the product styling and reviews; Codex interprets the evidence and prioritizes the next work. Individual reports distinguish each reviewer’s fresh checks from inherited evidence.

The desktop prototype delivers the useful authoring loop: paint and erase terrain, compose symbols, create places with lore, revise through layers and Undo, save/reopen an editable project, and export a PNG. These results support using the prototype. They do not establish unconditional acceptance of mobile navigation or completion of the penetration test.

The requested visual harmonization is present: plum binding, paper and ink, rubric actions, gold ornament, canonical UI typography and Roll Drauf identification. The small-screen header and Help layout defects are corrected, and paper-surface keyboard focus is more visible. Only `mapmaker.css` and the decorative brand block in `index.html` changed. All75 compared semantic-control/resource elements retain their attributes; all other1457 baseline files retain their contents. The source audit is in [codex-source-audit.json](codex-source-audit.json).

The highest-priority defect is **V3, medium: mobile place navigation hides the selected place behind the open inspector sheet**. Independent visual and simulated first-user reviewers reproduced it at390px and320px; visual evidence also covers667px landscape. Selection itself succeeds, which explains why state-based assertions can pass while the journey fails. A separate bounded Apply/Deploy should center the place in the uncovered map rectangle while preserving zoom, selection and place data. Verify opening the sheet and selecting another place with it already open at all three widths, plus desktop behavior.

**A1, low:** double-clicking a layer name does not start rename. The explicit rename button works. **V5, low:** Help initially scrolls to its Close button on very short screens, hiding the heading until the user scrolls upward. The first-user review also identifies two low discoverability traps: dragging an overlapping mountain can move the label above it, and renaming the project does not rename the map’s visible title label. The saved journey file retained the inadvertently moved label; recovery was available but was not fully demonstrated in that journey. These are practical usability follow-ups after V3. Physical pen/phone testing, Firefox/Safari and the campaign UI journey remain unverified. The missing symbol-search control was not a promised prototype capability and is not promoted to a new blocker.

**Security execution is incomplete** ([execution status](SECURITY_STATUS.md)). The independent Claude session read source and recorded hashes, then its automatic safety classifier rejected both the proposed dynamic penetration harness and the subsequently attempted static report. Neither a completed security report nor dynamic penetration results exist. The normal34-test suite and its input-validation cases remain ordinary regression evidence; they are not a penetration-test pass. No rejected harness/report was retried through another reviewer. Further independent security execution remains a required verification gap rather than an invented vulnerability or a clean bill of health.

**Recommendation:** accept the bounded aesthetic result, retain the prototype for desktop use, reopen Apply for V3, and keep overall mobile/security acceptance open. Do not expand that fix into server sync, a world database or broader editor parity. [Claude’s consolidated review](final-review.md), [action matrix](actions/matrix.json), [visual baseline review](visual/REVIEW.md), and [source audit](codex-source-audit.json) retain the concrete evidence. No production release occurred.

**Artifacts:** this interpretation and the linked proofs are retained as Monitor evidence. **Residual risks:** V3 medium remains unresolved; low usability findings and unexecuted security/device/browser checks remain named above. **Next step:** bounded V3 design and implementation, followed by targeted journey verification; a separately completed security test is still needed before calling security acceptance complete.
