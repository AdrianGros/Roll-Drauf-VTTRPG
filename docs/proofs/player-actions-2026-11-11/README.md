# Persönliche Aktionen – technische Live-Nachweise

Kampagnen → Tisch als Player/DM → eigenen verknüpften Charaktertoken wählen →
Belegen. Persistente drei Slots, Attributswurf, Waffenangriff, ausdrücklich manuelle
Zauberankündigung, gleiche Request-ID mit gleicher Antwort. Zwei echte Live-Reisen:
Firefox-Player mit Chromium-DM und Firefox-DM. TLS-Tunnel nur des Players getrennt,
Polling/WebSocket und Wiederverbindungen kurz unterbrochen; währenddessen DM-Wurf.
Nach nativer Wiederverbindung erscheint dessen persistente ID genau einmal. Eine
zweite Session empfängt keine der Nachrichten. 390-px-Bedienung im Screenshot.

`deployment.json` enthält beide Quell-/Image-Identitäten, additive Tabellen,
Backup-Lesbarkeit und Rückwege. Keine Wiederherstellung oder Rückrollung ausgeführt.
`cleanup.json` belegt Entfernung der eigenen synthetischen Daten und Credentials.
Keine menschliche Owner-Abnahme behauptet. Lokale aktuelle Nachprüfung: 36 API-/
Quittungsfälle und sechs Browserfälle; über den Paketumfang 55 verschiedene Fälle.
